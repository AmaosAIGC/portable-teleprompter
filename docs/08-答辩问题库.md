# 答辩问题库

按被问概率排序。答案要短，30 秒内说完，别背长段。

1. **和淘宝几十块的手机提词器有什么区别？**
   不依赖手机和 App，SD 卡直读，离线可用；成本 ¥200 内；显示参数可现场调；可多机共用一套脚本。
2. **为什么选 ESP32 不选 STM32？**
   BLE 内置省一个模块；PSRAM 支持大缓冲；SPI 屏与 FATFS 生态成熟；开发周期短。
3. **为什么用 BLE 不用经典蓝牙？**
   经典蓝牙 SPP 在 iOS 上不支持，BLE 双端通用且功耗低。
4. **中文字库怎么解决的？多大？**
   GB2312 16×16 约 260KB，24×24 约 576KB，放 Flash 分区；TXT 的 UTF-8/GBK 先探测编码再转 GB2312 区位码寻址。
5. **大字号滚动会不会卡？怎么保证流畅？**
   有 PSRAM 时双缓冲整帧 DMA；无 PSRAM 时条带渲染 + 脏行更新，只重绘进入窗口的行。
6. **速度怎么做到平滑？**
   以 px/s 为量纲，定时器累加固定步长，编码器增量做 EMA 滤波，避免按行滚动造成的速度跳变。
7. **为什么要镜像显示？**
   提词器靠 45° 分光镜反射，镜像后经反射才是正的；用 MADCTL 寄存器硬件镜像，不占 CPU。
8. **屏幕亮度不够怎么办？**
   IPS 高亮屏 + 遮光罩 + 提高对比度（黑底白字）；实测数据说明可读距离。
9. **丢包/断连怎么处理？**
   命令带 seq + ACK，超时重发 3 次；BLE 断线自动广播重连，重连后拉状态同步。
10. **手机端是自己做的吗？**
    微信小程序，BLE 直连，不需要装 App/审核，跨 iOS/安卓。
11. **这个系统的创新点在哪？**
    低成本离线方案 + 显示参数现场可调 + 双通道控制（BLE/2.4G 冗余），面向学生剧组的实际使用条件。
12. **脚本很长（10 万字小说）怎么处理？**
    SD 卡流式读取 + 行索引表，只把窗口附近的行读进内存，不整篇加载。
13. **掉电后设置会丢吗？**
    存 NVS，脚本存 SD 卡，重启恢复。
14. **为什么不做语音跟随？**
    本项目聚焦低成本与离线可用，语音识别需要联网或大算力，作为展望。
15. **测试数据可靠吗？怎么测的？**
    固定脚本样本、固定距离与光照，每组重复 20 次取平均，原始表在附录 C。
16. **成本控制具体多少？**
    BOM ¥198（不含工具），对比市售 ¥60–3000。
17. **组内你负责哪部分？**
    提词器硬件 + 固件 + 脚本管理 + 双通道控制；手机端与协议与组员共用。
18. **系统能扩展吗？**
    协议预留 opcode 位；可加多机同步（同一脚本 offset 广播）、语音跟随、云脚本。
19. **为什么屏这么小？**
    便携与成本约束；2.8/3.5 寸在 40–60cm 观看距离下 24 点阵可读，实测有数据支撑。
20. **遇到最大的困难是什么？**
    中文编码与渲染性能（说具体：字符编码探测、字库寻址、刷新策略），以及分光镜亮度。

## 不会答时的话术
「这一点我在实测中还没有覆盖，目前的做法是 X，后续会补测。」——比硬编好。
